# macOS MCP 管理器与 OpenAI Secure MCP Tunnel 研究

研究日期：2026-10-14。只阅读公开文档、仓库及源码；没有访问用户 Mac，没有运行候选软件，没有实际验证 ChatGPT 连接。

## 结论

可行，而且不需要从零造传输协议。这个产品应拆成三个明确部分：原生 macOS 进程管理、MCP 工具路由/聚合、官方 OpenAI Secure MCP Tunnel。管理本机 terminal 进程与 tunnel 是两回事；用户后续已经明确这里需要官方 tunnel。

已有接近的产品，但本次没有确认一个现成下载包同时满足“原生 SwiftUI/Liquid Glass、两种出口、官方 OpenAI tunnel、清楚的工具文档与默认拒绝敏感工具”。MCPMate 接近本机管理中心；Unified MCP Gateway 接近 Mac agent + 远端网关。两者不应直接等同于本次需求。

## OpenAI 当前官方路径

[Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) 已支持私有 MCP，通过本机 tunnel-client 发起出站 HTTPS，接入 ChatGPT 等受支持产品，无须对本机开放公网入站端口。客户端可连接 stdio 或 HTTP。其权限与 ChatGPT 自定义 MCP 使用权限分离：管理 tunnel 需组织 Tunnels Read + Manage；运行和选用需 Read + Use，并关联正确的 ChatGPT 工作区。官方当前默认请求截止时间 120 秒，序列化消息约 10 MiB，600 请求/分钟；具体以服务文档为准。

不能说“任意本机终端都能让 ChatGPT 网页直接连接”。必须有实现 MCP 的服务、可用隧道、运行中的客户端、正确身份/权限及产品配置。私有 tunnel 不能直接用于公开插件分发。

[当前 ChatGPT 接入文档](https://developers.openai.com/plugins/deploy/connect-chatgpt) 描述 Plugins → Add custom MCP server → Connection: Tunnel；公开连接则需 HTTPS/Streamable HTTP。旧教程的 Developer mode / Connectors 菜单名称可能与当前账户界面不同。不要承诺所有账户/套餐权限相同。工具或 schema 改动后，需 Refresh 并用新会话验证。

[官方 CLI onboarding 源码](https://github.com/openai/tunnel-client/blob/master/docs/onboarding.md) 明确支持：

- `init --sample sample_mcp_remote_no_auth --profile <name> --tunnel-id <id> --mcp-server-url <URL>`。
- `doctor --profile <name> --explain`。
- `run --profile <name>`。
- 运行密钥以 `CONTROL_PLANE_API_KEY` 环境变量传入。

因此可以把 HTTP URL 配成聚合 `/mcp` 或独立 `/servers/<id>/mcp`，并非只能使用固定演示服务器。初始化成功不代表实际可调用；只有用户完成 ChatGPT 安全工具调用才算端到端通过。

### 特别注意命名冲突

Supergateway 当前 README 指出聚合时同名能力默认首个胜出，另一项隐藏；可通过 `toolPrefix` 避免。产品不应静默采用这种行为。推荐稳定别名、显式路由表、重复名拒绝/可见告警；工具名长度也要受协议/客户端约束。保留原始工具名和来源名给用户看，导出“原名 → 聚合名 → 本机服务器”说明。

## 推荐产品架构

1. **SwiftUI App**：编辑 MCP executable/args/cwd，展示 PID/状态/日志、逐工具白名单、确认启动，管理已有官方 CLI。登录项和后台运行默认关闭。
2. **本机侧车**：只监听 loopback，配置 IPC 不走公开管理接口。stdio MCP 分开管理；一个聚合出口和每服务独立出口。精确白名单在 tools/list 和 tools/call 两处执行。
3. **官方 tunnel provider**：优先官方 tunnel-client；聚合一个 tunnel，独立模式每个出口独立 tunnel/profile。避免多个客户端抢同一 tunnel 导致请求随机落到错误服务。保留今后其他 provider 接口，但不先引入 ngrok/公网部署。
4. **工具说明**：模型看到清楚的 description、inputSchema、outputSchema/annotations；人看到来源、风险、允许的目录和账号、示例与限制。文档不能覆盖授权判断。
5. **状态分层**：本机进程运行、MCP initialize成功、工具发现成功、隧道进程运行、隧道ready、ChatGPT工具调用成功应分别呈现，不能一个绿灯覆盖全部。

## 安全与 OAuth

[OpenAI 认证文档](https://developers.openai.com/plugins/build/auth) 规定需要用户认证的 MCP 应实现符合规范的 OAuth 2.1；包含受保护资源元数据、授权服务元数据、PKCE、resource 参数和兼容的 client 注册/识别。普通静态 API key 并不自动等价于 ChatGPT OAuth。

官方 tunnel 已为私有连接提供传输入口和组织上下文，所以这个单用户原型无须另造公开 OAuth 服务。但 tunnel 不是任意上游业务权限的替代品；如后续上游 MCP 自身需要 OAuth，应保留其验证。OAuth 授权服务器的浏览器可达性也需单独处理。

最小权限建议：

- 默认不启动、不自动导入后运行、不公开网络端口。
- 不传整个父环境；密钥使用显式环境引用/安全输入，远离 args、日志、导出配置。
- 本机管理 IPC 与远端工具平面分离；禁止远端工具安装程序、添加服务器、改变白名单。
- 文件目录范围由 MCP 或 OS 约束，工具名白名单本身不能限制一个任意 shell 工具。
- 不把所有工具自动汇总到一个巨大目录。按用途分组，敏感写操作/终端/支付/凭据工具默认排除。
- 子进程退出立即撤下工具；重试、睡眠恢复、网络中断需准确状态，不静默扩大访问。
- 不默认捕获完整工具参数/结果；日志限量和脱敏。第三方工具描述与返回内容都是不可信内容。

## 本次实现决定

已按用户升级授权准备独立源码原型，选 SwiftUI + 官方 MCP SDK + 外部官方 tunnel-client，不直接复制上述成品。聚合实现仅针对工具，不宣称 MCP resources/prompts/sampling 等全协议透明代理。由于用户要求自行测试，本次没有运行任何原型、安装依赖或访问 Mac；源码交付与验收步骤另见原型 README。
